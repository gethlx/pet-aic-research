# 架构师 · 家庭连续事件检测评估方案 v1

> 提交者：架构师（Grok Bot，云端）｜修订依据：[11-09 评审「专题内 · 长录像评估方案 v0」行](../../reports/2026-11-09-调研评审与频率调整建议.md)（第 30 行）；[research/sources.md](../../research/sources.md) 第 67 行（专题强制口径）；[research/updates-log.md](../../research/updates-log.md) 2026-11-16 节与 [research/papers.md](../../research/papers.md) Wang、Atif 两行方法卡；产品专家 11-15 对 v1 §11 六个问题的答复，及其产品稿 [PR #23](https://github.com/gethlx/pet-aic-research/pull/23)（头 c635fe4，未合并）「设计起点建议 v0」第二至五节。晶晶 11-15 晚批准修订（老邪转达）。v0 原稿保留：[v0](架构师-家庭连续事件检测评估方案v0.md)。
> 整体证据档位：**B**。本文只定评估口径，不训练、不跑模型、不写代码；不授权采购、正式测试集、试点或开发。标「暂定」的数值是起步参数，不是验收线。

**改了什么、为什么（大白话）**：v0 判断「检出了」的标准太松：预测区间和真事件重叠够多，或者起点差不到 2 秒，就算命中。这样一段很长的预测只要起点碰巧对上，也会被算对；一个真事件连着报好几次警，也可能都算对，误报因此被少算，检出率因此被夸大。v1 改成一个真事件最多配一次报警，多出来的报警全算误报。起点准不准和主人多久收到通知分开记。误报按「能看清的录像一共多少小时」来算，没事发生的时段也算进去；被挡住、没录上、看不清的时段单独标出来，不混进分母。老家庭换个日子测和没见过的新家庭测分开报，并写清楚换一只新狗要不要先「注册」样本。简单基线和候选方法用同一份划分、同一套匹配规则、同一种定工作点的办法。每小时 1 次、5 次误报只是报告时用的刻度，不是合格线，合格线要等主人实际能忍多少的证据。这样改是为了让评估结果可信、换人也能复现，给后面的设计打基础。11-15 第二次更新：按产品专家的答复，把第一个场景定为「独处时连续吠叫」，允许同一事件隔一段时间再提醒（不算误报），加上「每小时推送次数」，通知延迟按 1 分钟和 5 分钟两档报，并写明新狗不注册也必须能用。【证据｜B】评审第 30 行原文；Wang/Atif 方法卡显示现有研究只报样本级 F1，没有每小时误报和家庭隔离。

## 0. 与 v0 相比不变的部分

- 按事件、按家庭评估，不按片段问答评估；主读数是「每小时误报（FA/h）下的事件召回率」。【证据｜B】v0 §结论；评审未否定此项。
- 测试单位是连续长录像（暂定单段 ≥1 小时，必须含空闲时段），不挑短片段。【证据｜B】v0 §2；Stephan 2021 摘要级：77 犬家庭独处录像中低发声、低活动是常态，不含空闲段就测不出真实误报。
- 三条简单基线、K9-Bench 只测理解层不测检测，沿用 v0 §3、§4。【证据｜B】v0 §3–4。
- 合成与增强数据只进训练集，测试集只用真实录像。【证据｜B】v0 §2；10-22 定论。

## 1. 数据口径

- 研发期可用开源数据（包括仅限非商用或学术用途的）、多源混合、AI 合成和采购数据，不因许可屏蔽；选数据以低成本、高质量可信为主。真正对外商用前再处理许可，由架构师提醒晶晶。【证据｜A】[10-22 讨论结论](2026-10-22-宠物组讨论结论与下周调研要求.md)第 11–13 行。
- 每段评估录像在清单里记来源、许可标签和「商用前要处理的点」，方便以后剔除重测。【证据｜B】[架构师-A不自采数据技术路径v0](架构师-A不自采数据技术路径v0.md)第 34 行的架构要求，套用到评估集。
- 用户侧采集可以写进以后的评估设计（例如上线后的持续监测），不当冷启动主数据。【证据｜A】同上 10-22 定论；用户本轮任务原文。
- 本文不启动采购或采集：v0 记录的「正式测试集（采购固定机位家庭长录像＋外包区间标注）暂缓（晶晶 11-02 定）」继续有效，口径本身不依赖它。【证据｜B】v0 §4 末句。

## 2. 事件与标注约定

- **事件**：可观察行为，不是意图或情绪。第一个验证场景定为「独处时连续吠叫」，主事件类别只有吠叫。【证据｜B】§11 答复 1（产品专家 11-15 答复，见 §11；产品稿 PR #23 头 c635fe4 未合并）；[11-09 评审](../../reports/2026-11-09-调研评审与频率调整建议.md)第 40 行。
- **辅助事件**：扒门、踱步第一轮不作为要检出的事件，但同样标起止，作辅助依据；其检出指标按同一规则单独报告，不进主指标。【证据｜B】§11 答复 1。
- **真事件区间** g = [s_g, e_g]：标注员标出起止。同类行为间隔不超过合并间隔 G 的视为同一事件（暂定 G = 5 秒；Wang 2022 的 L3 用 15 秒窗判定「重复吠叫」，可作上限参考）。G 写进标注规范并随数据集版本固定。【证据｜B】Wang 方法卡 ③；G 的取值为推断，暂定。
- **预测**：系统的一次「触发」= 主人会收到的一次通知。分两种输出：
  - 触发型：只有决策时刻 t_p（以及可选的估计起点 ŝ_p）。
  - 区间型：给出 p = [ŝ_p, ê_p]。
- **多犬**：主事件是「家里有狗在叫」，以家庭为单位，一次通知对一次事件，不区分是哪只狗。「哪只狗在叫」是次要指标，单独报告，允许拒答（§5）。【证据｜B】§11 答复 3。
- 双人标注抽样（暂定 ≥10% 时长），报告事件级一致率；分歧段由第三人裁定，裁定不了的标为「不可判」。【证据｜C】推断。

## 3. 录像时段分类与分母

每秒录像打一个状态：

| 状态 | 定义 | 进不进误报分母 | 段内触发 | 段内真事件 |
|---|---|---|---|---|
| 可评估 | 标注员能判断目标事件有没有发生，含无事件时段 | 进 | 正常匹配 | 进召回分母 |
| 遮挡 | 画面被挡、狗出画，标注员无法判断（若该类事件可单凭声音判断且音频完好，按可评估处理，并在清单注明「仅音频」） | 不进 | 不计 TP 也不计 FP，单列计数 | 不进召回分母，单列计数 |
| 缺录 | 设备掉线、文件缺失或损坏 | 不进 | 不存在 | 无法知道，单列缺录时长 |
| 不可判 | 有录像但标注员裁定不了（含 §2 无法裁定的分歧） | 不进 | 同遮挡 | 同遮挡 |

- **误报分母** T_eval = 所有「可评估」秒数之和（小时），**包含无事件时段**。【证据｜B】评审第 30 行；Bilen 等 2020（PSDS）也把 FP 率定义为 FP 数 / 数据集总时长。
- 跨边界的真事件：与不可评估时段重叠超过一半的整件剔除并单列；否则保留。【证据｜C】推断，暂定。
- 必须同时报：总录像时长、T_eval、可评估占比、各状态时长，以及「不可评估段内的触发数」。另报一个保守上界：把不可评估段内的触发全算作误报、分母改用总录像时长后的 FA/h。【证据｜C】推断：防止靠把难段标成不可判来压低误报。

## 4. 匹配规则（一对一）

1. **合格对**：预测 p 与真事件 g 同类别，且：
   - 触发型：t_p ∈ [s_g − c, e_g + D]，c 为提前容差（暂定 1 秒），D 为事件结束后的容差，取可用延迟上限 5 分钟（短促的一阵叫结束后几分钟内收到提醒仍有用）。【证据｜C】D 由 §11 答复 4「5 分钟以内算可用」推出，为推断。
   - 区间型：|p∩g| / |p| ≥ 0.5（预测大部分落在真事件内，过长的预测区间不合格），且 |p∩g| / |g| ≥ 0.3（暂定）。
   - **起点接近不再单独构成命中**，v0 的「起点相差 ≤2 秒即命中」删除。
2. **一对一**：在所有合格对上求最大匹配，每个真事件最多配一个预测，每个预测最多配一个真事件；匹配数相同时取起点误差绝对值之和最小的方案。按时间排序的流式触发里，等价于「每个真事件取最早的合格触发」。
3. **再提醒间隔 R**：真事件 g 配上第一次触发后，与 g 构成合格对的其余触发按时间顺序判断：距上一次「有效提醒」（首次匹配或上一次有效再提醒）≥ R 的，算「有效再提醒」，不算误报、也不重复计 TP，并成为新的计时起点；< R 的，算重复触发。R 取值待定，产品倾向不短于 10 分钟【证据｜C】§11 答复 2，产品标「倾向」。在 R 定下来之前，主表同时报 R = ∞（等同 11-09 原口径，g 内多出的触发全算误报）和 R = 10 分钟两套结果。【证据｜B】§11 答复 2；两套并报为推断。
4. **计数**：配上的预测 = TP；没配上的真事件 = FN；有效再提醒单列计数；其余没配上的预测 = FP。FP 再分三类单列：
   - 重复触发：与某个已配对真事件构成合格对、但既没被选中、也不满足再提醒间隔的触发（同一真事件里未到间隔的第 2、3…次报警）；
   - 串类触发：时间上落在别类真事件内的触发；
   - 纯误报：其余。
   三类都计入 FA/h。【证据｜B】评审第 30 行「同一真事件的剩余重复触发计入误报」；再提醒间隔是按 §11 答复 2 的细化，理由见处理表第 3 条。
- 说明：PSDS 允许多个检测共同构成一个 TP，本文不采用，按评审要求一对一。【证据｜B】[psds_eval 说明](https://github.com/j-bernardi/psds_eval)「More than one detection can contribute to a single true positive」。
- 区间阈值 0.5/0.3、容差 c、D 均为暂定，固定后对所有方法相同；另报阈值敏感性（如 0.3/0.1 与 0.7/0.5 两档）。【证据｜C】推断。

## 5. 指标与公式

记 N_g = 可评估真事件数，T_eval 单位为小时。

| 指标 | 公式 | 说明 |
|---|---|---|
| 事件召回率 | R = TP / N_g；漏报率 = 1 − R | 主读数之一 |
| 每小时误报 | FA/h = FP / T_eval | 主读数之一；同时报重复、串类、纯误报三项各自的 /h |
| 每事件重复报警 | 重复触发数 / TP | 打扰成本的直接读数 |
| 每小时推送次数 | (TP + 有效再提醒 + FP) / T_eval | 单列；真事件的提醒和误报都算进去，反映主人实际收到多少条 |
| 每个独处日误报提醒数 | 按录像日：当日 FP / 1 个独处日 | 单列参照，对应产品暂定值「独处一天误报提醒不超过 1 次」（推断，非门槛，见 §6） |
| 精确率 | P = TP / (TP + FP) | 次要，便于和文献对照 |
| 起点误差 | Δ = ŝ_p − s_g（仅 TP；触发型无 ŝ_p 时用 t_p） | 报带符号中位数、\|Δ\| 中位数和 P90；用于回看片段定位 |
| 通知延迟 | L = t_notify − s_g（仅 TP） | 报中位数和 P90；另报两个延迟工作点：及时召回率 R@1min、R@5min = 延迟不超过该值的 TP / N_g；5 分钟以内算可用 |
| 归因（次要，仅多犬家庭） | 覆盖率 = 给出犬 ID 的 TP / TP；覆盖内正确率 = 犬 ID 正确 / 给出犬 ID 的 TP | 允许拒答，拒答不算错但计入覆盖率；不进主指标 |
| 片段级 F1（1 秒一格） | 按 sed_eval 口径 | 次要，和文献对齐 |
| 风险—覆盖曲线 | 三档把握下拒答率与错误率 | 沿用 v0 |

- **起点误差和通知延迟分开**：前者问「系统说事件从哪开始」准不准，后者问「主人多久收到」。离线评估要求因果（流式）运行：t 时刻的决策只用 ≤ t 的数据，t_notify = 决策时刻 + 声明的固定管线开销。非因果方法不报延迟，标「不适用」。端到端实测延迟（网络、推送）留到原型阶段另测。【证据｜B】评审第 30 行「起点误差另记，通知延迟单列」；因果约束为推断。
- 延迟工作点 1 分钟、5 分钟：10 秒不作门槛；以后若有「邻居投诉、主人需要当场应对」的证据再收紧，目前待定。【证据｜B】§11 答复 4。
- **置信区间**：所有主读数按家庭做整群自助抽样（cluster bootstrap），报 95% 区间；家庭数太少时只作描述（暂定 < 5 户不报区间）。【证据｜C】推断：同一家庭的录像不独立，按片段抽样会让区间偏窄。
- 分层：事件类别、白天/夜视、单犬/多犬分开报，不用总分代替（沿用 v0）。单犬家庭和多犬家庭必须分开报；国内多犬家庭占比没有数据，不做加权合并。【证据｜B】v0 §1；§11 答复 3。

## 6. 工作点

- 对每个方法扫描决策阈值，画「召回率—FA/h」曲线（一对一口径）。
- **定阈值只在开发集上做**：在开发集上找到使 FA/h ≈ 1 和 ≈ 5 的阈值，原样用到测试集，测试集报实际的 FA/h 和召回率；另附测试集上的完整曲线。不允许在测试集上调阈值。【证据｜C】推断：这是「同一工作点」的可执行定义。
- 每小时 1 次、5 次**只作报告工作点**，不是产品门槛；主人能接受的误报容忍度回到实际主人场景证据再定。【证据｜B】评审第 30 行末句；§11 答复 6。
- 容忍度的证据来源（**待调研**）：① 应用商店评论和黑猫投诉里「误报太多、关了提醒」一类的话；② 厂商帮助文档和默认设置（勿扰、休眠、灵敏度、冷却时间）；③ 智能家居和安防领域关于告警疲劳的研究。【证据｜B】§11 答复 6；厂商把「误报→勿扰/休眠/灵敏度」写成标准处置见 [市场洞察](../../market/insights.md) 第 17 行，「一天多少误报、提醒后采取什么行动」仍是待查问题见同文件第 58 行。
- 产品稿的暂定值「独处一天误报提醒不超过 1 次」只作参照列（§5「每个独处日误报提醒数」），不作门槛。【证据｜C】产品稿 PR #23 第四节，产品专家自标推断。

## 7. 划分、分组报告与新犬注册

- **未见家庭**：按家庭划分，测试家庭（及其所有狗）不出现在训练集和开发集。
- **同家庭跨会话**：同一家庭较早的会话做训练或注册，较晚的会话做测试，两者至少隔 1 天（暂定），并记录间隔天数。
- 两组**分开报告，不合并成一个总分**；每组都报家庭数、犬数、T_eval、N_g。【证据｜B】评审第 30 行；Wang/Atif 方法卡均为样本级随机切分、未按犬隔离，正是 v1 要避免的做法。
- **新犬注册**：产品原则是不注册也必须能用，注册只用来提升效果【证据｜B】§11 答复 5。每个方法必须声明是否需要为新狗提供注册样本，**0 段（不注册）的结果必须单列**，作为未见家庭的主读数。
  - 不需要的，标「注册 0」，直接在未见家庭上测。
  - 需要的，记录注册段数、总时长和主人标注工作量（分钟），并按 0、1、5、20 段画召回率曲线（沿用 v0 刻度）。产品倾向注册最多 5 段、几分钟内完成【证据｜C】§11 答复 5，产品标「倾向」。若某方法要录很多段（超过 5 段）才能达到可用水平，就和「冷启动不能靠用户采集」冲突，结果标红报晶晶定，不自行判定可用。【证据｜B】§11 答复 5；产品稿 PR #23 第四节 H5 停止条件。注册段取自该家庭最早的会话，这段时长从测试 T_eval 中剔除。【证据｜B】评审第 30 行「记录新犬是否需要注册」；v0 §2。
- 划分以带哈希的清单文件固定（录像 ID、家庭 ID、犬 ID、会话时间、状态标注版本），所有方法共用。【证据｜C】推断，为可复现。

## 8. 基线与候选的公平比较

- 基线与候选使用**同一划分清单、同一匹配规则与参数、同一定工作点流程、同一时段状态标注**。【证据｜B】评审第 30 行。
- 超参数只在开发集上调；记录每个方法的计算量、每小时录像推理耗时和是否因果。【证据｜C】推断。
- 候选方法至少要在两组（未见家庭、同家庭跨会话）的同一工作点上同时超过三条基线才算有能力；只在一组上赢要如实写。【证据｜B】v0「至少超过三条简单基线」，分组要求为本次补充。

## 12. 未核实与限制

- 所有「暂定」数值（合并间隔 5 秒、容差 1 秒、区间阈值 0.5/0.3、跨会话间隔 1 天、少于 5 户不报区间、≥10% 双标）都是推断，需在第一份真实长录像上做敏感性检查后再固定。【证据｜C】
- 再提醒间隔 R 待定（产品倾向 ≥10 分钟）；事件结束后容差 D = 5 分钟由「5 分钟以内算可用」推出；产品暂定「独处一天误报 ≤1 次」未经数据验证。【证据｜C】
- 多犬家庭占比没有国内数据，单犬、多犬结果不能加权成总体。【证据｜B】§11 答复 3。
- 产品对齐依据的 PR #23 尚未合并，答复原文经老邪转达；若 PR #23 审后改动，§11 需同步。【证据｜B】
- Protopopova 2016 的检测方式以 PR #22 合并后的结论为准。【证据｜C】
- Stephan 2021 只读到摘要级。【证据｜B】
- 目前没有满足「家庭连续长录像＋事件区间＋可按家庭划分＋使用权清楚」的数据；本口径能否落地取决于数据路径，由晶晶决定是否以及何时启动采购或采集。【证据｜B】updates-log 11-16 节；v0 §4。
