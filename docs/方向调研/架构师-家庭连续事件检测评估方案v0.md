# 架构师 · 家庭连续事件检测评估方案 v0（供 2026-11-09 轮）
> 提交者：架构师（Grok bot，云端）｜依据：reports/2026-11-02-本期调研评审与修正方案.md:75–77、:155；导航账本.md:80（核心四问未覆盖）。约束：不自采、可多源混合＋合成＋采购；产品方向不动；本文只定评估口径，不训练、不跑模型。

## 结论
按事件、按家庭评估，不按片段问答评估。主指标是「每小时误报次数」下的事件召回率；测试集用连续长录像，按家庭和会话隔离；至少要超过三条简单基线才算有能力。K9-Bench 只能拿来测切出事件之后的理解层，不能测检测。

## 1. 指标（误报和漏报）
| 指标 | 定义 | 用途 |
|---|---|---|
| 事件召回率、漏报率 | 真事件被检出的比例：预测区间与真区间 IoU ≥0.3，或起点相差 ≤2 秒，就算命中（阈值暂定） | 漏报 |
| 每小时误报（FA/h） | 每小时连续录像里，没对上任何真事件的触发次数 | 误报，家庭场景主指标 |
| 工作点 | 报告 FA/h ≤1、≤5 时各自的召回率（阈值暂定，由产品定容忍度） | 取舍 |
| 片段级 F1（1 秒一格） | 按 sed_eval 口径 | 次要，用来和文献对齐 |
| 触发延迟 | 事件开始到触发的秒数，取中位数和 P90 | 实时性 |
| 风险—覆盖曲线 | 三档把握下，拒答率和错误率的关系 | 对应「三档把握」 |
所有指标按事件类别（吠叫、扒门、踱步等）、白天和夜视、单犬和多犬分层报告，不用总分代替。

## 2. 样本切分
- 测试单位是**连续长录像**（≥1 小时，包含空闲时段），不用挑好的短片段，否则 FA/h 测不出来。
- 隔离：同一家庭、同一只狗不能同时出现在训练集和测试集；另设一组跨会话测试（用同一家庭较早的会话训练，较晚的会话测试）。
- 合成数据和增强数据只进训练集，测试集只用真实录像（沿用 10-22 的定论）。
- 注册负担：按每只狗注册 0、1、5、20 段样本，画召回率曲线（Babu 等人用的是 5 段吠声）。

## 3. 简单基线（必须超过）
1. 画面运动能量阈值＋声音能量阈值触发（不用模型）。
2. 现成的狗检测和跟踪（开源检测器）＋位移规则。
3. 声音自监督模型（AVES 或 BEATs）冻结做特征，后面接线性吠叫检测，再和基线 1 的运动信号取「或」。

## 4. K9-Bench 怎么用，用什么替代
- 不能用来测检测：它是挑好的片段加选择题，没有连续流，也没有事件区间；MC 约 40%（随机水平 20%）只代表它测的那些任务。
- 可以这样用：把检出的事件片段送去测理解层，只挑和家庭场景对得上的题型，分任务报告；评分机制和标签来源的偏差要单独列为限制。许可是 CC BY-NC 4.0 加使用条款，只能研究用。
- 替代或补充（都只能研究用，许可待核）：Babu 等人的多犬音视频基准（arXiv 2610.21011，46 段视频、213 个吠叫事件，有区间）作为小型开发集；InterPet4D 的 113 个场次（第一人称视角，不是固定机位）测跨会话；采购固定机位家庭长录像，外包做事件区间标注，作为正式测试集，要花钱，需要晶晶批准。

## 5. 给 11-09 检索的具体要求
找「家庭连续监控＋事件区间标注」的犬或宠物数据和论文。对每一份都核对：录像时长、空闲占比、家庭数量、有没有按家庭隔离、有没有报告 FA/h 或可以换算成 FA/h。找不到就如实记缺口，不凑数。
